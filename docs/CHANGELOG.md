# 变更记录

本文件记录用户可见的变化。实现细节、测量数据与设计取舍在 [TECHNICAL.md](TECHNICAL.md) 与 [PERFORMANCE.md](PERFORMANCE.md)。

格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [2.0.0] — 2026-11-08

### 新增

- **一键自更新**：侧栏 Fairy 字标右上出现「可更新」胶囊 —— 插件自己向 npm registry 查版本（宿主的 `ctx.remote.pluginManager.listVersions`，结果缓存 6 小时，离线 / 失败时静默，不打扰也不报错）。点开是确认浮层：当前版本 → 新版本、从 npm 下载并替换当前插件，安装进度分步显示（检查版本 / 移除旧版本 / 下载并安装 / 回滚）；装完按宿主返回的结果提示「刷新页面」或「重启 DSH 后生效」。
- 只对「从 npm 安装」的插件生效：`link:` 本地目录安装没有 registry 来源，宿主会拒绝更新，此时不显示胶囊、也不做假按钮。
- 预览调试：`localStorage['fairy.zzz.update.debug'] = JSON.stringify({ latest: '9.9.9', installed: '2.0.0' })` 可以直接演一遍胶囊与浮层（只走假进度，不会真的安装）。

### 修复

- **账户菜单里「设置」右侧的 Ctrl+, 几乎看不见**：根因是皮肤里「新会话」按钮的一行规则 `[class*="_kbd"],[class*="_key"],[class*="_separator"]` 只有第一个选择器带了容器前缀，后两个变成了全局规则，把「新会话」按钮的墨黑字色刷到了账户菜单的快捷键上（快捷键的实际类名是 `_keys_` / `_key_`）。现在后两个选择器也限定进 `.wtg9ga_newSession`，并单独把菜单快捷键的对比度抬到 0.56（浅色 0.52）—— 读得清，但仍明显暗于菜单项标题，不会比「设置」本身更抢眼。

### 变更

- 版本号 1.7.7 → 2.0.0：自更新是用户可见的新能力，按语义化版本升主版本。

## [1.7.7] — 2026-11-07

### 变更

- **开场动画恢复原片颜色**：v1.7.0 给开机视频套了 `grayscale(.45) contrast(1.05) brightness(.84) saturate(.78)`，实测把画面平均饱和度从 .235 压到 .136、亮度从 102 压到 77，和原片一比就是「发灰」。开场动画是插件里唯一的彩色素材，不该跟着皮肤一起变灰：现在只保留一层极轻的对比校正（`saturate(1.04) contrast(1.02) brightness(1.02)`），铺底的模糊图也从去色压暗改回 `blur(46px)` 的彩色模糊。
- 扫描线与暗角相应减弱（1px/3px 黑线 .30 → .10，径向压暗 .72 → .46），保留一点 CRT 质感但不吃颜色。四帧实测：亮度 76.6 → 100.0（原片 101.8），饱和度 .136 → .255（原片 .235）。

## [1.7.6] — 2026-11-07

### 新增

- **眼徽呼吸拆成五层**：巩膜、虹膜外圈、虹膜、瞳仁、高光各自一个节点，幅度与相位错开（相位依次领先 0 / 45 / 90 / 180 毫秒），看起来是眼球由内向外的层层起伏，不再是整只眼一起缩一下。
- **思考态眼皮跟着呼吸开合**：思考 / 执行期间上半眼皮随同一个相位上下合动（下压 14.5–15.5 个单位、竖向压到 .55–1），白月牙一伸一缩；待机仍是固定的睁眼形状。

### 变更

- 呼吸周期 1.6s → 1.4s，缓动换成 `cubic-bezier(.72,0,.28,1)` 的三角波；采样仍是 15fps，五层各自只在数值变化时写一次 `transform`。
- 半闭眼的裁切不再固定：只改裁切路径里那条 path 的 `transform`，不重写 `d`。眼皮动画与关掉的 A/B 差落在噪声内（见 [PERFORMANCE.md](PERFORMANCE.md)）。

### 修复

- **工作态花屏切片里的眼睛还停在旧形状**：5 份横向切片各自带一份眼睛副本，那些副本的裁切走的是 CSS 里的 `url(#fz3-lid-clip)`，解析到别处的静态副本、不跟着下压，于是每次花屏那一瞬间都像回到了改动前的半闭眼。改成组件内所有 `.fz3-anatomy` 一律指向主眼那条独占 `clipPath`。
- **眼睑切口那条白边**：眼皮下压处的白色巩膜与深蓝眼睑之间有一道抗锯齿过渡带，128px 下读成一条亮边。改成沿切口压一条同色（`#1f2573`）描边，和裁切路径共用同一个 `transform`，跟着眼皮走；主眼那份 `#fz3-lid-edge` 在运行时改名 `#fz3-lid-edge-main`，花屏克隆里的副本保持隐藏。
- **思考态的半闭眼之前其实一直没动**：裁切路径在页面里有 8 份同名副本（主眼 1 + 花屏克隆 5 + 侧栏字标 2），浏览器按文档顺序只认最前面那份，写进主眼那份的 `transform` 没有任何效果。改成给主眼独占一个 `#fz3-lid-clip-main`、再用行内 `clip-path` 指过去，眼皮这才真的跟着呼吸一开一合。
- **待机态眼睛中间横着一条深蓝弧线**：切口描边 `#fz3-lid-edge` 在运行时被改名成 `#fz3-lid-edge-main`，而 CSS 只有 `#fz3-lid-edge{display:none}` 一条默认隐藏规则——改名之后它不再匹配，SVG 默认可见，于是待机时那条描边一直露在外面；思考态因为眼皮正好压在它上面才看不出来。改成两个 id 都默认 `display:none`，只在 `.fz3-eye[data-lid="thinking"]` / `.fz3-layer[data-lid="thinking"]` 下显示 `-main`。
